The shape of it

How the sandbox is wired

The sandbox runs the production server unchanged against fake data on a private VM. Two things make it safe to leave running: real data never reaches the VM, and the endpoint is never exposed to the internet.

Synthetic data, private endpoint

The test environment

  • ✓ Synthetic rows of the same shape as real PLM data
  • ✓ No auth, bound to 127.0.0.1, reached over an SSH tunnel
  • ✓ Column-scoped mcp_readonly role is the database backstop
  • ✓ smoke_test.py drives every tool → 9/9
Same code, three auth modes

Auth is config, not a rebuild

  • ✓ build_auth() picks the mode from environment variables alone
  • ✓ No OAuth vars set → unauthenticated, for local and private testing
  • ✓ Proxy vars set → AzureProvider (ChatGPT signs in through Entra)
  • ✓ Token vars set → JWTVerifier (validates bearer tokens)

03 · Authentication modes

Three ways to authenticate

The server has three authentication modes, picked at startup by build_auth() from which environment variables are set. Toggle the env-var groups below and watch the exact branch fire. The sandbox's unauthenticated run and a full OAuth run are the same code — only the configuration differs.

Proxy vars win when both are set — they're checked first in build_auth(). Set neither for local dev.
auth.py · build_auth(settings)
def build_auth(settings) -> AuthProvider | None:
    if (client_id and client_secret and tenant_id and base_url):
        log.info("OAuth enabled (Azure proxy, base_url=…)")
        return AzureProvider(…)        # DCR/CIMD + PKCE
    if (issuer_url and jwks_uri and audience):
        log.info("OAuth enabled (token validation, issuer=…)")
        return JWTVerifier(…)          # validate bearer JWTs
    log.warning("running WITHOUT authentication (local dev only)")
    return None
04 · Beyond the sandbox

Taking the sandbox public

The sandbox is deliberately private: no auth, localhost-only, reached over SSH. Exposing the same server for real use takes two changes — a public HTTPS front end, and switching the server out of no-auth into its OAuth-proxy mode so users sign in through Entra.

Public DNS name
Give the VM a stable public hostname so a certificate can be issued for it and ChatGPT has a fixed URL to connect to.
Open 80 + 443
Add inbound NSG rules for HTTP 80 (certificate challenge) and HTTPS 443. The endpoint stops being SSH-only.
HTTPS reverse proxy
A reverse proxy terminates TLS on 443 and forwards to the server on 127.0.0.1:8000, so the app itself never faces the internet directly.
Single Entra app
api://<id> + scope pg.read, manifest token v2, a client secret, and redirect /auth/callback — one app registration the proxy logs users in through.
Switch to OAuth mode
Set the four PGMCP_OAUTH_* proxy vars and a base URL, then restart. build_auth() returns an AzureProvider and the endpoint requires a token.
Postgres stays local
The server still reaches Postgres over 127.0.0.1, so the database never needs to open 5432 to anything beyond the VM.
What carries over unchanged. The synthetic data, the column-scoped mcp_readonly role, and the server binary are exactly the same. Going public adds a TLS front end and turns on authentication — it does not touch the data layer or the application code.

06 · Day-two

Operate & verify

How to confirm the test deploy is healthy and exercise it. Service commands run on the VM; the smoke test and tunnel run from your laptop.

End-to-end smoke test
$ uv run python scripts/smoke_test.py --url http://127.0.0.1:8000/mcp/
Drives every tool. Expect 9/9 checks passed and exit 0.
No-auth startup log
$ uv run python main.py
Logs running WITHOUT authentication, database pool opened, policy validated against DB: 5 tables, 2 templates, then Uvicorn running on http://127.0.0.1:8000.
Reach it from a laptop
$ ssh -L 8000:127.0.0.1:8000 azureuser@<vm>
Then point the client at http://127.0.0.1:8000/mcp/ — the only way in.
Role is read-only
$ psql -U mcp_readonly -d mg_dwh -c "INSERT INTO centric_8_plm.styles(id) VALUES ('x')"
Fails: cannot execute INSERT in a read-only transaction. SELECT of whitelisted columns works.
Flip on OAuth
# set the 4 PGMCP_OAUTH_* proxy vars → restart
Log changes to OAuth enabled (Azure proxy, base_url=…); curl -i .../mcp/ with no token → 401.
Regenerate fixtures
$ uv run python scripts/generate_synthetic_sql.py > scripts/synthetic_load.sql
stderr prints Generated rows: … + sample style codes; the .sql is git-ignored.
Note: the sandbox is synthetic-data-only and never internet-facing. To test with authentication, set the PGMCP_OAUTH_* vars against your own tenant and restart — the server starts requiring a token.
