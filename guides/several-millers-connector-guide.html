The decision

Why a VM & Caddy — not Container Apps

Spec 004 planned to run the server on Azure Container Apps. That path was blocked: registering the Microsoft.App resource provider is a subscription-level action, and the operator is only Contributor on the resource group. Spec 005 routes around it — the VM already hosts Postgres and the server, so nothing subscription-level is required.

Blocked path · spec 004

Container Apps

  • ✗ Needs Microsoft.App provider registered (subscription)
  • ✗ Postgres must open to the VNet (pg_hba, subnet NSG, static IP)
  • ✗ ACR build + Key Vault access policy + managed identity
  • ✗ Outside the operator's RG-Contributor access
As-built · spec 005

Server on the VM + Caddy

  • ✓ Caddy auto-issues a Let's Encrypt cert for the free DNS name
  • ✓ Server binds 127.0.0.1:8000 under systemd — only Caddy is public
  • ✓ Postgres stays localhost — no VNet, no pg_hba, no public 5432
  • ✓ Built entirely with RG-Contributor + Cloud App Admin

07 · Day-two

Operate & verify

How to confirm the connector is healthy, watch what it's doing, and recover it. The service commands run on the VM over SSH; the curl checks work from anywhere.

Service health
$ systemctl status pg-mcp-server
Expect active (running). Recover with sudo systemctl restart pg-mcp-server.
Startup logs
$ journalctl -u pg-mcp-server -f
Look for OAuth enabled (Azure proxy…) and policy validated against DB: 5 tables, 2 templates.
Auth is enforced
$ curl -i https://smpgmcp.westus.cloudapp.azure.com/mcp/
A request with no token must return 401 Unauthorized — tools are unreachable without a JWT.
Discovery is published
$ curl …/.well-known/oauth-protected-resource/mcp
Returns OAuth metadata — the resource, the authorization server, and scope pg.read.
HTTPS / Caddy
$ sudo systemctl reload caddy · journalctl -u caddy -f
Caddy auto-renews the Let's Encrypt cert; reload it after editing the Caddyfile.
Database role
$ psql -U mcp_readonly -d mg_dwh -c "SELECT 1"
SELECT works; any write fails with cannot execute INSERT in a read-only transaction.
Before you change the connector: a ChatGPT Business connector is immutable after publish — to change the server URL or OAuth settings you delete and recreate it. And keep PGMCP_OAUTH_BASE_URL exactly equal to the public host with no trailing slash, or discovery and redirects break.
